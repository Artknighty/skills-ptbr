# Formato do MISSION.md

O `MISSION.md` fica na raiz do workspace. Ele registra o _motivo_ pelo qual o usuário está aprendendo este assunto. Toda decisão de ensino (o que ensinar em seguida, quais recursos apresentar, quais exercícios montar) deve remeter a este documento.

## Modelo

```md
# Missão: {Assunto}

## Por quê
{1 a 3 frases. O objetivo concreto, do mundo real, que o usuário está buscando. O que muda na vida ou no trabalho dele quando tiver essa habilidade? Evite enquadramentos abstratos como "entender X"; insista no resultado por trás disso.}

## Sucesso é
- {Uma coisa específica e observável que o usuário vai conseguir fazer}
- {Outra coisa específica}
- {…}

## Restrições
- {Tempo, orçamento, compromissos já assumidos, preferências de aprendizado, qualquer coisa que limite a abordagem}

## Fora do escopo
- {Assuntos vizinhos que o usuário explicitamente não quer perseguir agora, protegendo a zona de desenvolvimento proximal}
```

## Regras

- **Uma missão por workspace.** Se o usuário quer aprender duas coisas sem relação entre si, são dois workspaces.
- **Concreto em vez de abstrato.** "Correr uma meia maratona até outubro" ganha de "ficar em forma". "Entregar uma CLI em Rust para o meu time" ganha de "aprender Rust".
- **Questione a vagueza.** Se o usuário não consegue dizer o porquê, entreviste-o antes de escrever qualquer coisa. Uma missão ruim é pior do que nenhuma missão.
- **Revise quando a realidade mudar.** Missões mudam. Quando o objetivo do usuário mudar, atualize este arquivo: não deixe uma missão obsoleta guiando as próximas sessões.
- **Seja breve.** Se o `MISSION.md` passar de uma tela, ele deixou de ser uma bússola e virou um plano.
